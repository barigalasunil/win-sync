# win-sync: UX Improvements and Markdown Export

**Date:** 2026-09-23
**Status:** Approved design
**Related spec:** `2026-09-23-interactive-cli-design.md`

## Goal

Improve the win-sync CLI experience and add human-readable Markdown export:

1. `win-sync` with no arguments defaults to the backup scan + interactive table (with `backup` kept as an alias)
2. ASCII art banner for "win-sync" displayed at startup
3. Terminal window automatically maximized on launch (Windows)
4. Rename the "Save Managed Only" option to clarify that manual apps are excluded
5. Add Markdown (.md) export alongside the existing JSON backup

## Approach

Follow the existing single-responsibility module pattern. Extend in place; no new framework or command-routing refactor. Commander stays as the CLI parser.

## Modules

### New `src/banner.js`

Two exports:

- `maximizeTerminal()` — Maximizes the console window via Win32 P/Invoke through PowerShell. Only invoked on `win32`. Wrapped in try/catch; must never crash the tool or emit errors. The invoked command:

  ```
  Add-Type -TypeDefinition 'using System;using System.Runtime.InteropServices;public class W{[DllImport("kernel32.dll")]public static extern IntPtr GetConsoleWindow();[DllImport("user32.dll")]public static extern bool ShowWindow(IntPtr h,int c);}';
  $h=[W]::GetConsoleWindow(); [W]::ShowWindow($h,3) | Out-Null
  ```

  No-op (silently) when stdout is piped/redirected (no attached console).

- `printBanner()` — Prints the hardcoded "win-sync" ASCII art (below) colored with chalk (cyan art + a small tagline line).

  ```
   _    _           _   _____ _ _
  | |  | |         | | /  ___(_) |
  | |  | | ___  ___| | \ `--. _| |_
  | |/\| |/ _ \/ __| |  `--. \ | __|
  \  /\  /  __/\__ \_| /\__/ / | |_
   \/  \/ \___||___(_) \____/|_|\__|
  ```

### New `src/markdown-generator.js`

Single export: `generateMarkdown(payload, { versions = {}, includeManualApps = true })` returning a Markdown string. Pure function; no I/O.

Buffers use an escape helper for table cells (pipe `|`, backtick, and newlines) so package names cannot corrupt tables.

Output structure:

```
# Windows Development Setup Backup
**Generated:** <local date/time> **Total Packages:** <N>

## Summary
| Category | Count | Status |
|----------|-------|--------|
| Winget Apps | <n> | ✅ Auto-restorable |
| NPM Globals | <n> | ✅ Auto-restorable |
| PIP Packages | <n> | ✅ Auto-restorable |
| Manual Apps | <n> | ⚠️ Requires manual download |

## Winget Apps (<n> packages)
| Package Name | Version |
|--------------|---------|
| <id> | <version from versions.winget, fallback "—"> |

## NPM Global Packages (<n> packages)
| Package | Version |
|---------|---------|
| <name> | <version from versions.npm, fallback "—"> |

## PIP Packages (<n> packages)
| Package | Version |
|---------|---------|
| <name> | <version> |

## Manual Apps
⚠️ **Warning:** These apps are not in Winget and must be downloaded manually.

| Name | Version | Publisher |
|------|---------|-----------|
| <name> | <version> | <publisher> |

*Generated by win-sync CLI tool*
```

Behavior:

- Header `**Total Packages:**` = winget + npm + pip + manual counts (same figure as the Summary table categories).
- `includeManualApps: false` → summary Manual count shows 0, Manual Apps section omitted entirely.
- Empty category in the Summary table still shows a row with count 0.
- Manual Apps section shown with "No manual apps found" line when the list is empty and the section is rendered.
- Emoji in the Summary table are literal Unicode characters (✅ ⚠️) — no ANSI/color codes anywhere in output.

### `index.js`

- Invoke `maximizeTerminal()` then `printBanner()` once, before `program.parse`.
- Default behavior: if `program.args.length === 0`, run `runBackup()`.
- `backup` subcommand remains an alias running the same logic; `restore` unchanged.
- `win-sync --help` / `--version` still work (banner prints before parse; commander handles the flags).

### `src/backup.js`

**Version side channel (no contrary change to the JSON payload schema):**

- winget: while parsing the existing `winget export` JSON, build `{ [packageId]: version }` from `pkg.Version`.
- npm: while parsing the existing `npm list -g --depth=0 --json`, build `{ [name]: version }` from `dependencies[name].version`.
- pip: versions already live in the payload (`{name, version}`).
- The side-channel data is passed only to the Markdown generator; `win-sync-setup.json` schema is unchanged.

**Choice prompt** (in order):

```
(B) Backup (JSON)
(M) Save as Markdown only
(A) Save as Both (JSON + Markdown)
(S) Save Auto-Restorable Only (exclude manual apps)
(D) Discard and exit
```

**Option → action matrix:**

| Choice    | JSON file   | Markdown file |
|-----------|-------------|---------------|
| B         | ✅ full (incl. manual) | — |
| M         | —                       | ✅ full |
| A         | ✅ full (incl. manual)  | ✅ full |
| S         | ✅ managed only         | — |
| D         | nothing written         | — |

- Option S reuses existing `buildBackupPayload(data, false)` (manual_apps: `[]`).
- Options B and A reuse `buildBackupPayload(data, true)`.
- JSON filename: `win-sync-setup.json`. Markdown filename: `win-sync-setup.md`. Both written to `process.cwd()`.
- Manual apps reminder text (existing) still printed when JSON includes manual apps.
- Success messages with absolute paths:
  - `✓ JSON saved to: <cwd>\win-sync-setup.json`
  - `✓ Markdown saved to: <cwd>\win-sync-setup.md`
- Each write is wrapped in try/catch: on failure print a red error for that file and continue rather than crash.

## Error handling

- Terminal maximize failures are silent (caught).
- File write failures produce a red message per file and do not abort unrelated saves.
- No changes to restore error paths.

## Testing

### `test/markdown-generator.test.js`

- Full backup renders all four sections and correct summary counts.
- `includeManualApps: false` omits the Manual Apps section and shows Manual 0.
- Winget/NPM versions come from the versions map; falls back to `—` when the map is missing entries.
- PIP versions come from the payload.
- A package name containing `|` is escaped and does not corrupt the table.
- Empty categories still render a summary row with 0.

### `test/backup.test.js`

- New tests for the version side-channel builders (pure functions exported from backup.js for testability).

### `test/ui.test.js`

- Unchanged (choice prompt lives in backup.js; no ui.js signature changes).
